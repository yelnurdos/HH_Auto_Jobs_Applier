Режим работы: исполнитель пишет код, архитектор проводит ревью по итоговому diff.

## Задача

Восстановить поиск с настройками пользователя и проверить оценку первых трёх реальных вакансий через `openai/gpt-6-luna`. При проверке не отправлять отклики, не поднимать резюме и не отправлять сообщения в Telegram.

## Подтверждённая причина

1. `PlaywrightJobManager.set_advanced_search_params()` использует старую страницу `/search/vacancy/advanced` и старые поля формы.
2. При живой проверке этот адрес перенаправил на `/search/vacancy` (HTTP 200). Старого поля `vacancysearch__keywords-input` там нет. Есть обычный `search-input` и кнопка «Фильтры».
3. Код игнорирует отсутствие формы и неудачи `safe_fill`/`safe_click`. Итоговый запрос предыдущего запуска содержал `text=` вместо `text=data`; регионы также не применились.
4. В предыдущем запуске конечная страница показала «Страница временно недоступна», «Ошибка 502». `get_vacancies_from_page()` счёл отсутствие карточек пустой выдачей. Причинная связь пустого запроса и самой ошибки 502 НЕ доказана.
5. При последующей проверке `/search/vacancy?text=data` работал: HTTP 200, 50 карточек, страница сообщала о 3712 вакансиях. Это общая выдача, БЕЗ регионов пользователя; число не является ожидаемым результатом исправленного поиска.

## Уже работает — не переделывать

- Авторизация hh.ru с сохранённой сессией и чтение резюме.
- Подключение OpenRouter: короткий запрос и оценка синтетической вакансии через существующий код прошли; фактическая модель — `openai/gpt-6-luna`.
- Селектор карточек `[data-qa="vacancy-serp__vacancy"]`: при исследовании нашёл 50 карточек.
- Ключ лежит в локальных секретах. Не выводить ключи, cookies, пароли и содержимое секретных файлов.

## Настройки для приёмки

Источник: `data_folder/search_config/search_config.yaml`, прочитать актуальную версию перед запуском.

- `keywords: data`, `job_title: data`.
- Регионы: `Астана, Алматы`.
- `search_field`: название вакансии, название компании и описание — все включены.
- `show_20: true`, `only_with_salary: false`.
- Чёрный список компаний сохранить; не оценивать его как фильтр формы hh.ru.
- Не менять настройки, чтобы получить больше результатов. Локальные настройки и секреты не коммитить.

## План реализации

### 1. Исправить вход в форму и установку фильтров

- Открывать обычную выдачу и новую панель «Фильтры»; не зависеть от старого `/advanced` и перехода через рекомендованные вакансии резюме.
- Сохранить контракт `set_advanced_search_params(search_params, resume_id)`, чтобы не менять вызывающие компоненты без необходимости.
- Дождаться поля панели, заполнить ключевые слова и проверить фактическое значение перед отправкой.
- Устанавливать флажки в нужное состояние, а не инвертировать кликом. Учитывать явные `false` и существующие значения по умолчанию.
- Выбрать оба региона через подсказки; подтвердить выбранные регионы в интерфейсе и/или конечном адресе.
- Применить размер выдачи 20 через актуальный элемент; при необходимости он находится вне панели.
- Для остальных настроек из `SearchConfig`: перенести заданные фильтры на новые элементы. Если конкретный заданный фильтр не поддержан или не удалось его применить, остановить поиск с понятной ошибкой. Не выполнять расширенный поиск с молча отброшенными условиями.
- Нажать конкретную кнопку применения панели, дождаться окончания перехода/обновления. Сохранить окончательный адрес в `self.search_page_url`.
- Не использовать широкие `//*[contains(., ...)]`, которые могут выбрать весь документ, и произвольный первый `input`.

### 2. Различать ошибку страницы и пустую выдачу

- При открытии выдачи/следующей страницы проверять ответ навигации и видимую страницу ошибки: ошибка может отображаться и при HTTP 200.
- Для временных 502/503/504 и сетевых сбоев: максимум 3 попытки, небольшая задержка, повтор того же адреса с сохранением фильтров. Никаких бесконечных повторов.
- При исчерпании попыток — явная ошибка; не возвращать `[]` и не писать «вакансий нет».
- Возвращать `[]` только при подтверждённой пустой выдаче. Если нет ни карточек, ни явного признака пустой выдачи, сообщать об изменившейся/незагруженной странице.
- Пагинация должна сохранять ключевые слова, регионы и остальные параметры. После посещения вакансии запрос следующей страницы должен использовать сохранённый адрес выдачи.
- Не маскировать сбой поисковой страницы общим `except`, после которого парсятся остатки предыдущей страницы.

### 3. Проверить без внешних изменений

- Сделать воспроизводимый ограниченный запуск (отдельный скрипт проверки допустим; большой новый режим приложения не нужен).
- Использовать существующую сессию, выбранное по настройкам резюме и действующий поиск; оценить максимум 3 вакансии.
- Вызывать сбор вакансии и оценку непосредственно, без `start_applying`, `send_repsonse` и `apply_job`.
- ВАЖНО: `get_resume_content_from_browser()` безусловно вызывает `raise_resume()`. На время проверки блокировать этот метод явно; одного изменения `RAISE_RESUME` недостаточно.
- ВАЖНО: в `SEARCH_MODE` счётчики основного цикла не увеличиваются, поэтому `max_applies_num=3` не ограничивает пробный поиск тремя вакансиями.
- Отключить Telegram-обработчики ошибок/капчи именно в процессе проверки. При необходимости ручного входа/капчи — понятная остановка. Не менять постоянные настройки уведомлений.
- На проверке отключить резервные модели только в памяти, чтобы подтвердить именно Luna. Сохранить фактическую модель из ответа, а не только название в конфигурации.
- Всегда закрывать браузер в `finally`; задать ограничение времени запуска.
- Отчёт в `data_folder/output/`: адрес поиска, подтверждённые фильтры, количество разобранных карточек, название/ссылка/оценка/обоснование для проверенных вакансий, фактическая модель, статус, число отправленных откликов `0`.

## Тесты

Нужны регрессионные тесты, которые воспроизводят поведение, а не только проверяют вызов нового метода:

1. Старый `/advanced` больше не используется; новая панель получает `data`, обе области/города и правильные состояния флажков. Повторное применение не снимает флажки.
2. Невозможно применить заданный регион или ключевые слова — ошибка до отправки поиска.
3. 502 → рабочая выдача: ограниченный повтор, фильтры сохранены, карточки получены.
4. Постоянная 502, в том числе страница ошибки с HTTP 200: явная ошибка после лимита, не `[]`.
5. Подтверждённая пустая выдача возвращает `[]`; неизвестная разметка — ошибку.
6. Переход на следующую страницу после просмотра вакансии сохраняет параметры поиска.
7. Пробный запуск не вызывает отправку отклика, поднятие резюме и Telegram; останавливается после трёх вакансий.

Тесты с локальной HTML-страницей Playwright предпочтительны для поведения формы; сетевые ответы можно подменять. Не отправлять реальные сообщения из тестов. Добавить целевой файл, например `tests/test_playwright_search.py`.

Запустить целевые тесты и полный набор: `.venv/bin/python -m pytest tests`. Сначала зафиксировать исходные падения. В `tests/test_search_customizer.py` уже заметны устаревшие ожидания (`set_advanced_search_params` у `SearchCustomizer` вместо существующего `set_search_parameters`); полный набор в исследовании не запускался. Не приписывать старые падения своему исправлению и не переписывать посторонние тесты ради зелёного результата.

### Ограничения

- Селекторы hh.ru (magritte, хэшированные классы) нестабильны; поэтому каждое «true»-направление фильтра применяется явно и проверяется по реальному состоянию (текст поля/URL/чекбоксы), а не принимается на веру.
- Размер выдачи: основной путь — UI-меню; на живом hh.ru после submit панели клики по меню могут теряться из-за перерисовки, поэтому есть гарантированный fallback через `items_on_page` в URL (параметр подтверждён live).
